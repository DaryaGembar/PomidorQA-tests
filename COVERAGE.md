# Матрица покрытия тестами — требования PomidorQA

Трассировка требований спецификации продукта к автотестам этого репозитория.
Обновлено: 2026-09-20.

**Легенда статусов:** ✅ покрыто · 🟡 частично · ❌ не покрыто

**Уровни тестов:**

- **E2E** — реальный браузер против живого стенда `aiqa.su` (`tests/e2e/`)
- **API** — HTTP к локальному мок-серверу бизнес-правил (`tests/api/`, мок в `src/pyramid/`)
- **Unit** — чистые функции без браузера и сети (`tests/unit/`)

## 4. Регистрация и вход

| Требование                                                          | Статус        | Покрытие                                                                                                                                                                                         |
| ------------------------------------------------------------------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Обязательные поля: имя, email, пароль                               | ✅ E2E        | `register-form` — пустая форма блокирует сабмит, все три поля `valueMissing`                                                                                                                     |
| Пароль не короче 8 символов                                         | ✅ E2E + Unit | `register-form` — 7 символов `tooShort`; unit — граница: 7 невалиден, ровно 8 валиден                                                                                                            |
| Email проверяется на формат                                         | ✅ E2E        | `register-form` — email без «@» даёт `typeMismatch`                                                                                                                                              |
| Email уже занят — понятная ошибка                                   | ✅ E2E + API  | `register-form` — ошибка «email уже зарегистрирован» от сервера; API-мок — повторная регистрация `409 email_taken`                                                                               |
| После регистрации — профиль с именем из формы, пояс `Europe/Moscow` | ✅ E2E        | `register-form` — редирект в каталог и авторизованная шапка; `profile-flow` — в профиле подставлено имя из регистрации; дефолтный пояс `Europe/Moscow` проверяется перед сменой в `profile-flow` |
| Неверный вход — ошибка без уточнения причины                        | ✅ E2E        | `login-error` — текст ошибки при неверном пароле и при несуществующем email идентичен                                                                                                            |

## 5. Профиль

| Требование                                                                         | Статус  | Покрытие                                                                                                                              |
| ---------------------------------------------------------------------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Поля: имя, Telegram, часовой пояс, «О себе» — сохраняются и возвращаются с сервера | ✅ E2E  | `profile-flow` — все четыре поля: сохранение → перезагрузка → значение пришло с сервера                                               |
| Часовой пояс — выбор из списка РФ                                                  | ✅ E2E  | `profile-flow` — контракт: полный список из 10 поясов сверяется с §14; перебор — каждый пояс сохраняется и возвращается с сервера     |
| Пояс профиля определяет отображение времени слотов                                 | 🟡 Unit | `slots.spec` — `formatSlotTime` даёт разное время для `Europe/Moscow` и `Asia/Yekaterinburg`; на живом стенде не проверяется          |
| Профиль виден другим участникам                                                    | 🟡 E2E  | `catalog-search`, `booking-flow` — гость видит имя хоста в каталоге и на карточке; остальные поля на странице участника не ассертятся |

## 6. Навыки

| Требование                                           | Статус | Покрытие                                                                                                                                                    |
| ---------------------------------------------------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Навык типа «могу помочь» добавляется и виден в блоке | ✅ E2E | `profile-flow`; во всех host-сценариях навык — входные данные для поиска в каталоге                                                                         |
| Название — свободный текст                           | ✅ E2E | уникальные теги с датой и UUID в каждом прогоне                                                                                                             |
| Два типа навыков: `can_help` / `want_to_learn`       | ✅ E2E | `profile-flow` — навык типа `want_to_learn` добавляется и появляется в блоке «Хочу разобрать» (у блока нет testid — осознанный CSS-локатор от подзаголовка) |
| Дубликат навыка того же типа нельзя добавить         | ✅ E2E | `profile-flow` — повторное добавление игнорируется для обоих типов; чип остаётся один, в т.ч. после перезагрузки                                            |
| Удаление своего навыка                               | ✅ E2E | `profile-flow` — кнопка «Убрать» на чипе; после перезагрузки чипов с этим навыком ноль                                                                      |

## 7. Слоты доступности

| Требование                                                       | Статус       | Покрытие                                                                                            |
| ---------------------------------------------------------------- | ------------ | --------------------------------------------------------------------------------------------------- |
| Создание слота: дата + время начала                              | ✅ E2E       | все host-сценарии: слот на завтра 12:00, появляется в списке свободных                              |
| Нельзя создать слот в прошлом                                    | 🟡 API       | мок — бронирование слота в прошлом `409 slot_in_past`; через UI создания слота на стенде не покрыто |
| Статусы `free` / `booked`                                        | ✅ E2E + API | мок — переход в `booked` после брони; E2E — поллинг свободного слота и ошибка второй брони          |
| Удаление своего свободного слота; забронированный удалить нельзя | ✅ E2E       | `slots` — свободный слот удаляется кнопкой «Удалить», после перезагрузки списка нет; `booking-cancel` — у забронированного слота кнопки нет, статус `booked` сохраняется |
| Фиксированная длительность 25 минут                              | ❌           | напрямую не проверяется (unit работает с произвольными интервалами)                                 |

## 8. Каталог участников

| Требование                                                  | Статус | Покрытие                                                                                                                                    |
| ----------------------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| В каталоге — только участники со свободным слотом в будущем | ✅ E2E | `catalog-search` — хост без слота не виден; после добавления слота появляется в выдаче (поллинг с `toPass`)                                 |
| Участник не видит себя в каталоге                           | ✅ E2E | `catalog-search` — хост ищет свой навык и не находит себя                                                                                   |
| Поиск по навыку «могу помочь»                               | ✅ E2E | `catalog-search` — поиск находит ровно одну карточку; пустая выдача для несуществующего навыка; результаты не накапливаются между запросами |

## 9. Страница участника

| Требование                                        | Статус | Покрытие                                                                                                               |
| ------------------------------------------------- | ------ | ---------------------------------------------------------------------------------------------------------------------- |
| Видны имя, навыки, свободные слоты в будущем      | 🟡 E2E | имя и слоты ассертятся (`booking-flow`, `catalog-search`); блок навыков и «О себе» на странице участника не ассертятся |
| Прошедшие и забронированные слоты не показываются | ❌     | не покрыто                                                                                                             |

## 10. Бронирование звонка

| Требование                                       | Статус       | Покрытие                                                                                                                                                           |
| ------------------------------------------------ | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Свой слот забронировать нельзя                   | 🟡 API       | мок — `409 cannot_book_own_slot`; через UI живого стенда не покрыто                                                                                                |
| Бронировать можно только `free` и в будущем      | ✅ API + E2E | мок — `slot_in_past`, `slot_already_booked`, `404 slot_not_found`; E2E — бронь только свободного слота                                                             |
| Успех: слот → `booked`, бронь → `confirmed`      | ✅ API + E2E | мок — `201` + `confirmed`; E2E — модалка «Забронировано», бронь в «Мои встречи» у обоих                                                                            |
| **Гонка: ровно одна бронь, второй видит ошибку** | ✅ API + E2E | API — два одновременных запроса дают строго `[201, 409]`; E2E — два гостя в разных контекстах: первый `success`, второй видит «Этот слот только что забронировали» |

## 11. Отмена бронирования

| Требование                                       | Статус | Покрытие                                                                                              |
| ------------------------------------------------ | ------ | ----------------------------------------------------------------------------------------------------- |
| Отмена со стороны гостя                          | ✅ E2E | `booking-cancel` — гость отменяет, бронь уходит в «Прошедшие и отменённые» у обоих после перезагрузки |
| Отмена со стороны ведущего слота                 | ❌     | не покрыто (тестируется только отмена гостем)                                                         |
| Отмена не позднее чем за 2 часа до звонка        | ❌     | не покрыто                                                                                            |
| После отмены слот снова `free` и доступен другим | ❌     | статус `cancelled` проверяется, возврат слота в выдачу — нет                                          |

## 12. Мои встречи

| Требование                                        | Статус | Покрытие                                                                                                     |
| ------------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------ |
| Брони видны обоим участникам: и ведущему, и гостю | ✅ E2E | `booking-flow` — после брони встреча видна в «Мои встречи» у обоих (поллинг с `toPass`)                      |
| Деление на «Ближайшие» и «Прошедшие и отменённые» | ✅ E2E | `booking-cancel` — отменённая встреча уходит во второй список, исчезает из «Ближайших»                       |
| Отмена доступна только из «Ближайших»             | 🟡 E2E | `booking-cancel` — отмена выполняется из списка «Ближайших»; отсутствие кнопки в другом списке не ассертится |

## 13. Критерии приёмки

| Критерий                                                                                          | Статус       | Покрытие                                                                                |
| ------------------------------------------------------------------------------------------------- | ------------ | --------------------------------------------------------------------------------------- |
| Основной путь целиком: регистрация → профиль+навык → слот → поиск → бронь → «Мои встречи» у обоих | ✅ E2E       | `booking-flow` — сценарий один в один с критерием приёмки                               |
| Нельзя забронировать собственный слот                                                             | 🟡 API       | мок-сервер                                                                              |
| Нельзя забронировать уже занятый слот                                                             | ✅ API + E2E | мок + гонка двух гостей в браузере                                                      |
| Нельзя создать слот в прошлом                                                                     | 🟡 API       | мок-сервер                                                                              |
| Нельзя отменить бронирование за час до звонка                                                     | ❌           | не покрыто                                                                              |
| Гонка за слот не даёт двух подтверждённых броней                                                  | ✅ API + E2E | двойное покрытие: детерминированно на моке (параллельные запросы) и сквозное в браузере |

## Итог

**Сильные зоны:** регистрация и валидация формы, вход и безопасность ошибки, редактирование профиля, навыки обоих типов (добавление, дубликаты, удаление), поиск и выдача каталога, жизненный цикл слота (создание, удаление свободного, запрет удаления забронированного), бронирование с двойным (API + E2E) покрытием гонки за слот, отмена гостем, «Мои встречи» у обоих участников.

**Осознанные разрывы (кандидаты в следующий этап):**

- слоты: 25-минутная длительность
- отмена: ведущим слота, запрет отмены позже чем за 2 часа, возврат слота в свободные
- страница участника: блок навыков и «О себе», скрытие прошедших/занятых слотов
- отображение времени слотов на живом стенде

Разрывы на UI живого стенда (свой слот, слот в прошлом) частично компенсируются API-уровнем на моке бизнес-правил — там же удобно проверять новые правила до появления UI-покрытия.
