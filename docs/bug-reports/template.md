## BR-NNN — Краткое название

| Поле | Значение |
| --- | --- |
| **Severity** | `S1 — блокер` · `S2 — критично` · `S3 — значимо` · `S4 — минор` |
| **Priority** | `P0` · `P1` · `P2` · `P3` |
| **Type** | `Functional` · `UI/UX` · `Performance` · `Security` · `API` · `Accessibility` · `Data` |
| **Status** | `New` · `Triaged` · `In progress` · `Fixed` · `Verified` · `Won't fix` · `Known` |
| **Component** | Например: `auth/register-form`, `catalog/search`, `booking/cancel` |
| **Reported by** | Имя репортера, дата |
| **Environment** | URL стенда, браузер, ОС, разрешение, авторизация (кто вошёл) |
| **Related requirement** | ID из coverage-matrix, например `R8.3` |
| **Related test** | Имя теста, например `e2e/known-defects` |

## Как выбирать Severity / Priority

| Severity | Что значит | Пример |
| --- | --- | --- |
| **S1 — блокер** | Ломает ключевой сценарий, нет workaround | Не работает регистрация; нельзя забронировать |
| **S2 — критично** | Серьёзный сценарий с workaround или часть аудитории теряет функциональность | Гонка за слот не защищена сервером (только UI) |
| **S3 — значимо** | Дефект UX / визуальный, воспроизводимый, но не блокирующий | Цвет кнопки на hover не соответствует гайду |
| **S4 — минор** | Косметика, edge case | Локализационная запятая вместо точки в одном месте |

| Priority | Что значит |
| --- | --- |
| **P0** | Чинить прямо сейчас (S1) |
| **P1** | В ближайшем релизе (S2) |
| **P2** | В бэклоге, приоритет по capacity (S3) |
| **P3** | Когда-нибудь, low (S4) |
