# KD-1 — Каталог ищет по навыкам обоих типов

| Поле | Значение |

| **Priority** | P2 |

### Summary
Поиск в каталоге участников возвращает людей по навыкам из раздела «хочу разобрать»,
хотя требование R8.3 разрешает искать только по разделу «могу помочь».

### Steps to Reproduce
1. Зарегистрировать пользователя Host
2. В профиле Host добавить навык `KnownDefect-1763846400000` в раздел **«хочу разобрать»**
3. Добавить свободный слот в будущем
4. Зарегистрировать второй аккаунт Guest, открыть каталог
5. В поиске ввести `KnownDefect-1763846400000`

### Expected Result
Выдача пустая (или с явным сообщением «ничего не найдено»), карточка Host не отображается.

### Actual Result
Карточка Host отображается в результатах поиска — фильтр каталога проходит по всем навыкам
участника, а не только по разделу «могу помочь».

### Evidence
- Скриншот выдачи каталога (в архиве прогона `e2e/known-defects`)
- Trace.zip с действиями поиска и DOM выдачи
- Воспроизводится детерминированно

### Impact
- **Кто затрагивается:** все гости, ищущие конкретную экспертизу — могут попасть к участнику,
  который только хочет разобраться, а не помогать
- **Частота:** always (детерминированно)
- **Workaround у пользователя:** нет
- **Затронутые тесты:** `e2e/known-defects` — зелёный за счёт `test.fail()`, статус в матрице `known defect`

### Root Cause (гипотеза)
Серверный (или клиентский) фильтр каталога не различает тип навыка `want_to_learn` /
`can_help`, индексирует оба. Подтверждение требует анализа API каталога и/или исходников
фронта (исходники продукта закрыты для тестирующего).

### Suggested Fix (направление)
Один из двух вариантов — требует решения PO:
1. Сузить фильтр каталога по навыкам только до раздела «могу помочь»
2. Переписать требование R8.3: разрешить поиск по обоим разделам

После решения один из вариантов:
- Удалить `test.fail()` в `e2e/known-defects`, статус `automated`
- Или удалить тест целиком, статус требования `automated`
