# BR-002 — Форма создания слота не блокирует выбор даты в прошлом

| Поле | Значение |

| **Priority** | P2 |
| **Type** | UI/UX |
| **Status** | New (требует триажа продуктом) |
| **Component** | `profile/slots-form` |
| **Reported by** | AQA, 27.09.2026 |
| **Environment** | `https://aiqa.su/pomidorqa`, Chromium 124 (Playwright bundled), desktop 1920×1080 |
| **Related requirement** | R7.2 — «Нельзя создать слот в прошлом» |

### Summary
Требование R7.2 запрещает создавать слоты в прошлом. Сервер это контролирует
(`409 slot_in_past`), но клиентская форма **не блокирует выбор прошедшей даты и времени** —
пользователь может заполнить всё, отправить и увидеть невнятное серверное сообщение
об ошибке вместо понятной валидации на клиенте.

### Steps to Reproduce
1. Зарегистрировать пользователя
2. Открыть «Мои встречи» → вкладка «Слоты» (или эквивалентный путь к форме создания слота)
3. В поле «Дата» выбрать **вчерашнее число**
4. В поле «Время» выбрать любое время, например, 10:00
5. Нажать «Добавить» / «Сохранить»

### Expected Result
Форма блокирует отправку **до запроса на сервер**:
- Поле «Дата» имеет `min={сегодня}` (или эквивалент)
- Либо нативная `required` + серверная проверка видна как валидационное сообщение рядом с полем
- Сообщение об ошибке понятное: «Нельзя создать слот в прошлом» — не «Internal Server Error» или
  «Что-то пошло не так»

### Actual Result
1. Клиент **не валидирует** прошедшую дату (поле `min` отсутствует или равен дефолту)
2. Запрос уходит на сервер, возвращается ошибка
3. Сообщение либо невнятное («Ошибка сервера»), либо в неожиданном месте — пользователь
   не понимает, что именно не так

### Evidence
- Скриншот формы с открытым календарём и активными датами в прошлом
- Network: POST /slots → 4xx с телом ответа
- Тестовый аккаунт: создаётся через `registerViaApi` в `tests/helpers/user.ts`, удаляется в `finally`

### Impact
- **Кто затрагивается:** все пользователи, добавляющие слоты
- **Частота:** воспроизводимо, всегда
- **Workaround:** пользователь должен догадаться поменять дату; для новичков это UX-стена
- **Затронутые тесты:** косвенно — `tests/e2e/slots.spec.ts` использует `tomorrow`, чтобы обойти проблему
  (то есть тесты знают о баге и обходят его, а пользователь — нет)

### Root Cause (гипотеза)
Клиентская валидация формы создания слота не проверяет диапазон дат. Поле `<input type="date">`
либо без `min`, либо `min` задан некорректно (например, в прошлом или с дефолтным
1970-01-01). Подтверждение требует инспекции чанка фронта.

### Suggested Fix
1. В `<input type="date">` поставить `min={new Date().toISOString().slice(0,10)}` (или эквивалент
   в локали пользователя)
2. В `<input type="time">` дополнительно проверить, что выбранное время не в прошлом, если дата = сегодня
3. На сабмите формы — клиентская проверка перед запросом
4. Серверное сообщение об ошибке (`409 slot_in_past`) — прокинуть в форму с человеческим текстом
