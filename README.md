## Что покрыто

**E2E — сквозные сценарии в реальном браузере на живом стенде:**

| Спека            | Сценарий                                                                                                                                                                                                                                              |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `booking-flow`   | полный путь: регистрация → навык → слот → поиск в каталоге → бронирование → «Мои встречи» у обоих участников. Плюс **гонка за слот**: два гостя бронируют один слот — первый получает успех, второй видит ошибку «Этот слот только что забронировали» |
| `booking-cancel` | отмена брони: встреча уходит в «Прошедшие и отменённые», её видят и гость, и хост после перезагрузки                                                                                                                                                  |
| `catalog-search` | поиск по навыку находит хоста со слотом; пустая выдача и сброс; хост без слота не попадает в каталог и не видит сам себя                                                                                                                              |
| `register-form`  | успешная регистрация через форму; валидация: пустая форма не отправляется, пароль короче 8 символов отклоняется                                                                                                                                       |
| `profile-flow`   | редактирование профиля: имя, часовой пояс, Telegram, «О себе» — сохранение и возврат значения с сервера; навыки обоих типов — «могу помочь» и «хочу разобрать»                                                                                        |
| `login-error`    | вход с неверными данными — одинаковая ошибка без уточнения причины (без раскрытия, существует ли email)                                                                                                                                               |

Многосессионные сценарии (хост + два гостя) работают в независимых контекстах браузера
с отдельными сессиями — как реальные разные пользователи.

**API** — бизнес-правила бронирования через HTTP к локальному мок-серверу:
успешное бронирование (201), запрет брони собственного слота и слота в прошлом (409), гонка за слот.

**Unit** — чистые функции: пересечение слотов по времени (включая граничные случаи «впритык» и вложенность), форматирование времени, валидация пароля.

## Подход

- **Page Object Model** — все локаторы и действия над страницей в `tests/pages/`, семантические
  локаторы (`getByRole`, `getByLabel`, `getByTestId`), никаких CSS/XPath без необходимости
- **Auto-waiting вместо пауз** — `expect(locator).toBeVisible()`, `expect(...).toPass()`,
  `expect.poll`; фиксированных `waitForTimeout` нет (закреплено ESLint-правилами)
- **Тестовые данные через API** — регистрация и удаление аккаунтов через тестовые эндпоинты,
  быстрее и стабильнее, чем через UI; уникальные пользователи и навыки на каждый прогон,
  чтобы прогоны не конкурировали на общем стенде
- **Гарантированная уборка** — удаление созданных аккаунтов в `finally` с каскадом
  (навыки → слоты → брони)
- **Диагностика падений** — `trace` и скриншоты сохраняются при падении и загружаются в артефакты CI

## CI — GitHub Actions

На каждый push в `main` и каждый PR пайплайн гоняет пять параллельных кубов:

- **Lint** — ESLint; упавший линт не запускает e2e на общем стенде
- **Unit** и **API** — быстрые уровни без браузера
- **E2E** — Chromium на живом стенде, 2 воркера; junit-таблица комментарием в PR
- **Notify Telegram** — статус всех кубов, длительность, ссылки; отчёты и артефакты
  падений (trace, скриншоты) — в артефактах прогона
- После зелёного CI на PR **AI-reviewer** (Claude Opus 5 через Polza.ai) публикует
  ревью диффа: двухпроходная проверка против TEST-CODEX и чеклиста

## Запуск

```bash
npm install
npx playwright install chromium

npm run test:unit   # unit — без сети и браузера
npm run test:api    # api — HTTP к локальному мок-серверу
npm run test:e2e    # e2e — реальный браузер на живом стенде
npm test            # все три уровня
npm run report      # HTML-отчёт последнего прогона
```

По умолчанию e2e идут на `https://aiqa.su`; направить на другой стенд:

```bash
POMIDORQA_BASE_URL=http://localhost:3000 npx playwright test --project=e2e
```

## Структура

```
src/pyramid/        — чистые функции (unit) и локальный мок-сервер бронирования (api)
tests/unit/         — тесты чистых функций
tests/api/          — бизнес-правила бронирования через HTTP
tests/e2e/          — сквозные пользовательские сценарии
tests/pages/        — Page Objects: локаторы и действия над страницами
tests/helpers/      — тестовые данные, роуты, API-хелперы регистрации/удаления
scripts/            — AI-reviewer: проверка PR через Polza.ai
docs/               — матрица покрытия, правила TEST-CODEX, чеклист REVIEW
.github/workflows/  — CI-пайплайн и AI-reviewer
```
